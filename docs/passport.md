# Паспорт проекта

## 1. Название проекта

Магазин обуви «Шаг» — настольное приложение (C# WPF) для просмотра каталога и управления товарами

## 2. Проблема

В магазине обуви данные о товарах и остатках разбросаны по бумажным записям и таблицам, поэтому клиент не видит актуальный ассортимент, а сотрудники тратят время на поиск нужной модели и сверку остатков.

## 3. Пользователи

- **Гость** — просматривает каталог без поиска, фильтров и сортировки.
- **Авторизованный клиент** — просматривает каталог товаров с фото, ценами, скидками и остатками.
- **Менеджер** — ищет, фильтрует и сортирует товары, просматривает заказы.
- **Администратор** — добавляет, редактирует и удаляет товары, управляет заказами.

## 4. Цель проекта

Создать настольное приложение с базой данных, в котором любой пользователь видит актуальный каталог и остатки, а менеджер и администратор быстро находят товары и управляют ими.

## 5. Метрики успеха

- Каталог из 30+ товаров открывается за < 2 секунд после входа.
- Поиск, фильтр по поставщику и сортировка по остатку обновляют список за < 1 секунды, без нажатия кнопки «найти».
- Администратор добавляет новый товар (заполнение формы и сохранение) за < 2 минут.
- 0 аварийных завершений при проверке по чек-листу тест-кейсов к занятию 13.

## 6. Границы (что НЕ делаем)

- Не делаем мобильное и веб-версии — только настольное приложение под Windows.
- Не подключаем онлайн-оплату и доставку — оформление заказа клиентом не входит в этап ДЭ.
- Не реализуем полное управление заказами для всех ролей на первом этапе — сначала каталог и товары.
- Не храним пароли в защищённом виде на учебном этапе (хеширование — вне границ проекта).

## 7. Риски

- Не успеем всё к дедлайну → приоритизация: сначала вход и каталог, затем поиск/фильтры, затем форма товара.
- Импорт данных заказчика окажется «грязным» (кодировка, пропуски, дубли) → готовим скрипт очистки и проверяем связи до загрузки.
- Ошибки при работе с фото товаров (большой размер, занятый файл) → ограничение 300×200, понятные сообщения, безопасное удаление старого файла.
- Конфликты при работе в одном репозитории → маленькие коммиты, push после каждого этапа.
